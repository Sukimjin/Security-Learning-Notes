# 系统日常运维操作指南

>  面向运维/交付实施岗位的日常运维操作手册，覆盖巡检、服务管理、日志查看、故障上报全流程。

---

## 一、日常巡检清单

### 1.1 每日巡检

| 巡检项 | 检查命令 | 正常标准 | 异常处理 |
|--------|---------|---------|---------|
| Docker 容器状态 | `docker ps` | 所有目标容器 Up | 重启异常容器 |
| Apache 服务状态 | `systemctl status apache2` | active (running) | `systemctl restart apache2` |
| MySQL 服务状态 | `systemctl status mysql` | active (running) | `systemctl restart mysql` |
| 磁盘空间 | `df -h` | 使用率 < 80% | 清理日志/临时文件 |
| 系统负载 | `uptime` | load < CPU 核数 | 排查高负载进程 |
| 内存使用 | `free -h` | 可用 > 20% | 排查内存占用进程 |
| Apache 错误日志 | `tail -50 /var/log/apache2/error.log` | 无频繁 ERROR | 根据错误排查 |
| MySQL 错误日志 | `tail -50 /var/log/mysql/error.log` | 无频繁 ERROR | 根据错误排查 |

### 1.2 每周巡检

| 巡检项 | 检查命令 | 说明 |
|--------|---------|------|
| 数据库备份 | `ls -la /backup/*.sql` | 确认备份文件存在且大小正常 |
| Docker 资源占用 | `docker system df` | 检查镜像/容器/卷占用 |
| 系统安全日志 | `journalctl --since "7 days ago" \| grep -i error` | 检查系统级错误 |
| 网络连接状态 | `ss -s` | 检查异常连接 |
| 定时任务 | `crontab -l` | 确认备份任务正常 |
| 日志文件大小 | `du -sh /var/log/*` | 日志未异常膨胀 |

### 1.3 每月巡检

| 巡检项 | 检查命令 | 说明 |
|--------|---------|------|
| 系统补丁更新 | `apt list --upgradable` | 检查可用更新 |
| Docker 清理 | `docker system prune` | 清理无用资源 |
| 用户权限审查 | 查看 `/etc/passwd` + MySQL 用户列表 | 确认无多余账号 |
| 防火墙规则审查 | `ufw status` / `iptables -L` | 确认规则无异常变更 |
| SSL 证书有效期 | `openssl s_client -connect host:443` | 到期前 30 天更换 |

## 二、服务重启操作

### 2.1 Docker 容器管理

```bash
# 查看运行中的容器
docker ps

# 重启单个容器
docker restart dvwa-lab

# 重启所有容器（docker-compose）
docker-compose restart

# 停止所有容器
docker-compose stop

# 启动所有容器
docker-compose start

# 重新创建容器（修改配置后）
docker-compose up -d --force-recreate
```

### 2.2 LAMP 服务管理

```bash
# Apache
systemctl restart apache2
systemctl reload apache2     # 重新加载配置（不断连接）

# MySQL
systemctl restart mysql

# PHP-FPM（如使用）
systemctl restart php8.1-fpm

# 按顺序重启（依赖关系）
systemctl restart mysql && systemctl restart apache2
```

> 注意 生产环境中重启服务前需确认：1) 无活跃连接 2) 已通知用户 3) 在维护窗口内操作

## 三、日志查看与归档

### 3.1 日志位置速查

| 服务 | 日志路径 | 说明 |
|------|---------|------|
| Apache 访问日志 | `/var/log/apache2/access.log` | 所有 HTTP 请求记录 |
| Apache 错误日志 | `/var/log/apache2/error.log` | PHP 错误、Apache 错误 |
| MySQL 错误日志 | `/var/log/mysql/error.log` | 数据库启动/运行错误 |
| MySQL 慢查询日志 | `/var/log/mysql/mysql-slow.log` | 执行超时查询（需开启） |
| 系统日志 | `/var/log/syslog` | 系统级事件 |
| Docker 容器日志 | `docker logs <容器名>` | 容器内应用日志 |
| 认证日志 | `/var/log/auth.log` | SSH 登录、sudo 操作 |

### 3.2 常用日志分析命令

```bash
# 实时查看最新日志
tail -f /var/log/apache2/access.log

# 查看今天的访问日志
grep "$(date +%d/%b/%Y)" /var/log/apache2/access.log

# 统计访问量 Top 10 IP
awk '{print $1}' /var/log/apache2/access.log | sort | uniq -c | sort -rn | head -10

# 查看错误日志中的 PHP Fatal
grep "Fatal error" /var/log/apache2/error.log | tail -20

# 查看失败的 SSH 登录尝试
grep "Failed password" /var/log/auth.log | tail -20

# Docker 容器日志（最近 100 行）
docker logs --tail 100 dvwa-lab

# Docker 容器日志（指定时间段）
docker logs --since "2026-08-14T08:00:00" --until "2026-08-14T18:00:00" dvwa-lab
```

### 3.3 日志归档

```bash
# 手动归档日志
tar -czf /backup/logs/apache2_$(date +%Y%m%d).tar.gz /var/log/apache2/

# 清理 30 天前的日志
find /var/log/apache2/ -name "*.log.*" -mtime +30 -delete

# 配置 logrotate（通常默认已配置）
cat /etc/logrotate.d/apache2
```

## 四、故障上报流程

### 4.1 故障分级

| 级别 | 定义 | 响应时间 | 示例 |
|------|------|---------|------|
| **P0 - 紧急** | 核心服务完全不可用 | 立即 | 靶场环境无法访问、数据库宕机 |
| **P1 - 高** | 部分功能不可用 | 30 分钟内 | 某个漏洞模块报错、上传功能失效 |
| **P2 - 中** | 性能下降但可用 | 2 小时内 | 页面响应慢、日志报错但不影响使用 |
| **P3 - 低** | 非功能性问题 | 24 小时内 | 文档错别字、UI 显示问题 |

### 4.2 故障处理流程

```
发现故障
  │
  ├── 1. 初步判断
  │   ├── 是什么故障？（服务不可用 / 功能异常 / 性能问题）
  │   ├── 影响范围？（全部用户 / 部分功能 / 单个页面）
  │   └── 故障级别？（P0/P1/P2/P3）
  │
  ├── 2. 记录故障信息
  │   ├── 时间：精确到分钟
  │   ├── 现象：报错信息截图 / 日志片段
  │   └── 环境：容器/服务状态快照
  │
  ├── 3. 尝试初判处理
  │   ├── 查看日志（参考第三章）
  │   ├── 查看排错手册：[故障排查手册](../01-DVWA靶场实训/环境部署与故障排查手册.md)
  │   ├── 尝试重启服务（参考第二章）
  │   └── 记录已尝试的操作和结果
  │
  ├── 4. 上报
  │   ├── P0/P1：立即电话/即时消息上报
  │   ├── P2：工单系统上报
  │   └── P3：邮件/周报上报
  │
  └── 5. 记录与复盘
      ├── 填写故障记录表（见下）
      ├── 根因分析
      └── 制定预防措施
```

### 4.3 故障记录模板

```markdown
### 故障编号：INC-2026-001
### 发生时间：2026-XX-XX HH:MM
### 故障级别：P0 / P1 / P2 / P3
### 故障现象：
（描述故障的具体表现，附报错截图/日志）

### 影响范围：
（受影响的服务/功能/用户数）

### 初判处理：
1. [操作1] → 结果：___
2. [操作2] → 结果：___

### 根因分析：
（故障的根本原因）

### 解决方案：
（最终采取的修复措施）

### 恢复时间：HH:MM（总耗时：XX 分钟）
### 预防措施：
（避免同类故障再次发生的措施）

### 处理人：___________
```

## 六、运维操作速查卡

| 场景 | 命令 |
|------|------|
| 查看服务状态 | `docker ps` / `systemctl status apache2 mysql` |
| 重启服务 | `docker-compose restart` / `systemctl restart apache2` |
| 查看实时日志 | `docker logs -f dvwa-lab` / `tail -f /var/log/apache2/error.log` |
| 查看磁盘 | `df -h` / `docker system df` |
| 查看资源占用 | `docker stats` / `top` / `htop` |
| 数据库备份 | `mysqldump -u root -p dvwa > backup.sql` |
| 清理 Docker | `docker system prune` |
| 查看端口 | `ss -tlnp` / `netstat -tlnp` |
| 查看防火墙 | `ufw status` / `iptables -L -n` |
| 查看系统用户 | `cat /etc/passwd \| grep -v nologin` |
