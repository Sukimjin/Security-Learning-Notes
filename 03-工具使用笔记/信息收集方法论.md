# 信息收集方法论（授权前提下的资产测绘）

> 授权测试 / 资产测绘场景下的信息收集方法梳理，强调「先授权、后探测」的合规边界。所有操作仅适用于已获授权的目标或自建靶场，未经授权对他人资产进行扫描属违法行为。

---

## 一、信息收集在安全工作中的位置

信息收集是渗透测试 / 风险评估 / 攻击面管理的**第一步**，目的是摸清目标资产的「暴露面」：有哪些域名、IP、端口、服务、指纹、敏感文件。信息越全，后续检测越精准，也能帮助防御方**收敛攻击面**。

| 阶段 | 目的 | 常见对象 |
|---|---|---|
| 资产发现 | 找到目标所有入口 | 域名、子域名、IP 段、C 段 |
| 指纹识别 | 判断技术与组件 | 中间件、框架、CMS、WAF、操作系统 |
| 敏感资产 | 找泄漏点 | 目录、备份文件、配置、接口文档 |
| 攻击面管理 | 持续监控暴露面 | 资产台账、变更监测 |

---

## 二、被动信息收集（不直接接触目标）

- **公开信息**：ICP 备案、WHOIS、DNS 记录、证书透明度日志（CT）
- **搜索引擎**：站内检索暴露的敏感文件、后台路径、历史快照
- **公开测绘平台**：第三方资产测绘数据（Fofa、Shodan 等，仅查询公开数据）
- **GitHub / 网盘**：检索目标相关的源码、配置泄漏（仅限授权排查）

## 三、主动信息收集（需授权）

- **子域名枚举**：字典爆破 + 搜索引擎 + 证书透明度，找边缘资产
- **端口 / 服务扫描**：用 Nmap 探测存活端口与服务版本（见 [`Nmap常用扫描命令.md`](Nmap常用扫描命令.md)）
- **指纹识别**：识别 CMS / 框架 / 中间件版本（见 [`dirsearch目录爆破.md`](dirsearch目录爆破.md)）
- **目录枚举**：探测敏感目录、备份文件、配置文件（dirsearch 等）

---

## 四、合规边界（重点）

1. **先授权后测试**：只对自有资产、客户明确授权的目标、或自建靶场（如 DVWA）进行主动探测
2. **控制探测强度**：扫描频率与并发需克制，避免影响目标业务
3. **不越界**：发现目标之外的其他资产，及时上报，不擅自扩大范围
4. **留存证据**：授权书、测试范围、时间窗做好记录，便于审计
