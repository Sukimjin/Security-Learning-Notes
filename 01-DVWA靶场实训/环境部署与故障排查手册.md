## 二、常见故障排查（10 个高频场景）

### 2.1 端口被占用（8080/80/3306）

**现象**：`docker-compose up` 或 `systemctl start apache2` 报 `port is already allocated` 或 `Address already in use`

**排查步骤**：

```bash
# Linux：查看占用端口的进程
ss -tlnp | grep :8080
# 或
netstat -tlnp | grep :8080

# Windows：查看占用端口的进程
netstat -ano | findstr :8080

# 杀掉占用进程（Linux）
kill -9 <PID>

# 或修改 docker-compose.yml 端口映射
ports:
  - "9090:80"   # 改为 9090
```

**预防**：部署前先执行 `ss -tlnp | grep -E ':(80|8080|3306)\s'` 确认端口空闲。

---

### 2.2 Docker 容器启动失败

**现象**：`docker ps -a` 显示容器状态为 `Exited` 或 `Restarting`

**排查步骤**：

```bash
# 查看容器日志（最关键）
docker logs <容器名或ID>

# 查看容器详情
docker inspect <容器名或ID>

# 查看容器资源使用
docker stats --no-stream

# 常见原因：
# 1. 镜像拉取不完整 → docker pull <镜像名> 重新拉取
# 2. 端口冲突 → 参考 2.1
# 3. 磁盘空间不足 → docker system prune 清理
# 4. 配置文件语法错误 → 检查 docker-compose.yml 缩进
```

---

### 2.3 数据库连接失败

**现象**：DVWA 页面提示 `Could not connect to the database` 或 `MySQL server has gone away`

**排查步骤**：

```bash
# 1. 检查 MySQL 服务状态
systemctl status mysql        # Linux
net start mysql               # Windows

# 2. 测试本地连接
mysql -u root -p
# 能连上说明服务正常，问题在应用配置

# 3. 检查 DVWA 数据库配置
cat /var/www/html/dvwa/config/config.inc.php
# 确认 db_server / db_user / db_password / db_database 正确

# 4. Docker 环境下检查容器间网络
docker network ls
docker network inspect dvwa-net

# 5. 检查 MySQL 端口监听
ss -tlnp | grep :3306
# 如果只监听 127.0.0.1:3306，远程连接会被拒绝
# 修改 /etc/mysql/mysql.conf.d/mysqld.cnf：
# bind-address = 0.0.0.0（如需远程访问）
```

### 2.4 DVWA 页面 403 Forbidden

**现象**：访问 `http://localhost:8080` 返回 403

**排查步骤**：

```bash
# 1. 检查 Apache 错误日志
tail -20 /var/log/apache2/error.log

# 2. 检查 DVWA 目录权限
ls -la /var/www/html/dvwa/
# Apache 用户（www-data）需要对目录有读取+执行权限

# 3. 修复权限
chown -R www-data:www-data /var/www/html/dvwa/
chmod -R 755 /var/www/html/dvwa/

# 4. 检查 Apache 配置中 Directory 指令
# 确保有 AllowOverride All
<Directory /var/www/html/dvwa/>
    AllowOverride All
    Require all granted
</Directory>

# 5. 重启 Apache
systemctl restart apache2
```

---

### 2.5 DVWA 页面 404 Not Found

**现象**：访问 DVWA 返回 404 页面不存在

**排查步骤**：

```bash
# 1. 确认 DVWA 文件实际存在
ls /var/www/html/dvwa/index.php

# 2. 检查 Apache DocumentRoot
grep -r "DocumentRoot" /etc/apache2/sites-enabled/
# 应指向 /var/www/html

# 3. 检查 URL 路径
# 正确：http://localhost/dvwa/ 或 http://localhost:8080/
# Docker 环境下根目录就是 DVWA，无需 /dvwa 子路径

# 4. 检查 Apache 模块
apache2ctl -M | grep rewrite
# 如未启用 rewrite 模块：
a2enmod rewrite
systemctl restart apache2
```

### 2.6 PHP 模块缺失

**现象**：DVWA setup 页面提示某些 PHP 模块未安装（如 `gd` / `mysqli` / `pdo_mysql`）

**排查步骤**：

```bash
# 1. 查看已安装的 PHP 模块
php -m

# 2. 安装缺失模块（Debian/Ubuntu）
apt-get install php-gd php-mysqli php-pdo-mysql -y

# 3. 重启 Apache 使模块生效
systemctl restart apache2

# 4. Docker 环境下
# 官方 DVWA 镜像通常已包含所需模块
# 如需自定义，可在 Dockerfile 中追加：
# RUN docker-php-ext-install mysqli pdo_mysql gd
```

### 2.7 LAMP 权限问题

**现象**：DVWA 无法写入文件（上传/日志功能失效），或页面报 `Permission denied`

**排查步骤**：

```bash
# 1. 确认 Apache 运行用户
ps aux | grep apache2
# 通常是 www-data

# 2. 检查 DVWA 目录属主
ls -la /var/www/html/dvwa/
# uploads/ 和 hackable/uploads/ 需要写权限

# 3. 修复关键目录权限
chown -R www-data:www-data /var/www/html/dvwa/uploads/
chown -R www-data:www-data /var/www/html/dvwa/hackable/uploads/
chmod -R 777 /var/www/html/dvwa/hackable/uploads/
# 注意：777 仅用于靶场环境，生产环境应使用 755 + 属主

# 4. 检查 PHP 临时目录
php -i | grep upload_tmp_dir
# 确保临时目录存在且可写
mkdir -p /tmp/php_upload/
chmod 777 /tmp/php_upload/
```

### 2.8 MySQL 远程连接被拒绝

**现象**：其他主机连接 MySQL 报 `Host 'xxx' is not allowed to connect to this MySQL server`

**排查步骤**：

```bash
# 1. 检查 MySQL 监听地址
ss -tlnp | grep :3306
# 如果只监听 127.0.0.1，远程无法连接

# 2. 修改 bind-address
# 编辑 /etc/mysql/mysql.conf.d/mysqld.cnf
# bind-address = 0.0.0.0
systemctl restart mysql

# 3. 授权远程访问（仅限靶场环境）
mysql -u root -p
# 在 MySQL 中执行：
# CREATE USER 'dvwa'@'%' IDENTIFIED BY 'password';
# GRANT ALL PRIVILEGES ON dvwa.* TO 'dvwa'@'%';
# FLUSH PRIVILEGES;

# 4. 检查防火墙
ufw allow 3306/tcp    # 或 iptables -A INPUT -p tcp --dport 3306 -j ACCEPT
```

### 2.9 Docker 镜像拉取超时

**现象**：`docker pull` 长时间无响应或报 `timeout`

**排查步骤**：

```bash
# 1. 配置国内镜像加速
# 编辑 /etc/docker/daemon.json（Linux）
# 或 Docker Desktop → Settings → Docker Engine（Windows/Mac）
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com",
    "https://docker.mirrors.ustc.edu.cn"
  ]
}

# 2. 重启 Docker
systemctl restart docker          # Linux
# Windows/Mac：重启 Docker Desktop

# 3. 重新拉取
docker pull vulnerables/web-dvwa:latest

# 4. 如果仍然超时，尝试手动导入
# 从其他机器导出：docker save -o dvwa.tar vulnerables/web-dvwa
# 传到目标机器：docker load -i dvwa.tar
```

### 2.10 磁盘空间不足

**现象**：Docker 操作报 `no space left on device`，或 MySQL/Apache 异常

**排查步骤**：

```bash
# 1. 查看磁盘使用情况
df -h

# 2. 查看 Docker 占用空间
docker system df

# 3. 清理无用镜像和容器
docker system prune -a    # 清理所有未使用的资源
# 或选择性清理
docker container prune    # 清理停止的容器
docker image prune        # 清理悬空镜像

# 4. 清理系统日志
journalctl --vacuum-size=100M

# 5. 清理 APT 缓存（Debian/Ubuntu）
apt-get clean && apt-get autoremove -y
```

## 三、环境巡检与日常维护

### 3.1 服务状态检查

```bash
# Docker 环境
docker ps                    # 查看运行中的容器
docker stats --no-stream     # 查看资源使用

# LAMP 环境
systemctl status apache2     # Apache 状态
systemctl status mysql       # MySQL 状态
systemctl status php*-fpm    # PHP-FPM 状态（如使用）
```

### 3.2 日志轮转配置

```bash
# Apache 日志轮转（logrotate 默认已配置）
cat /etc/logrotate.d/apache2

# 手动触发日志轮转
logrotate -f /etc/logrotate.d/apache2

# Docker 容器日志大小限制
# 在 /etc/docker/daemon.json 中添加：
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

### 3.3 数据库备份

```bash
# 导出 DVWA 数据库
mysqldump -u root -p dvwa > dvwa_backup_$(date +%Y%m%d).sql

# 恢复数据库
mysql -u root -p dvwa < dvwa_backup_20260814.sql

# Docker 环境下在容器内执行
docker exec <容器名> mysqldump -u root -p dvwa > dvwa_backup.sql
```

### 3.4 磁盘空间监控

```bash
# 查看磁盘使用
df -h

# 查找大文件（>100MB）
find / -type f -size +100M 2>/dev/null | head -20

# 查看 Docker 日志大小
du -sh /var/lib/docker/containers/*/*-json.log
```

### 3.5 定期维护清单

| 维护项 | 频率 | 命令 |
|--------|------|------|
| 检查容器/服务状态 | 每天 | `docker ps` / `systemctl status` |
| 查看磁盘空间 | 每周 | `df -h` |
| 数据库备份 | 每周 | `mysqldump` |
| 清理 Docker 无用资源 | 每月 | `docker system prune` |
| 检查日志异常 | 每天 | `tail -100 /var/log/apache2/error.log` |
| 更新系统补丁 | 每月 | `apt-get update && apt-get upgrade` |

## 四、故障排查通用思路

```
发现问题
  ├── 是什么现象？（报错信息 / 页面表现 / 日志记录）
  ├── 什么时候开始？（部署后 / 运行中 / 修改配置后）
  ├── 影响范围？（单个功能 / 整个服务 / 多个服务）
  │
  ├── 查日志
  │   ├── Apache: /var/log/apache2/error.log
  │   ├── MySQL: /var/log/mysql/error.log
  │   ├── Docker: docker logs <容器名>
  │   └── 系统: journalctl -u <服务名>
  │
  ├── 查网络
  │   ├── 端口监听: ss -tlnp
  │   ├── 防火墙: ufw status / iptables -L
  │   └── 容器网络: docker network inspect <网络名>
  │
  ├── 查权限
  │   ├── 文件属主: ls -la
  │   ├── 进程用户: ps aux
  │   └── SELinux/AppArmor: getenforce / aa-status
  │
  └── 查配置
      ├── PHP: php -i | grep <关键词>
      ├── Apache: apache2ctl -M（已加载模块）
      └── MySQL: SHOW VARIABLES LIKE '<关键词>';
```
