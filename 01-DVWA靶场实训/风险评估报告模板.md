## 二、风险等级评定标准

参考 CVSS 3.1 评分体系，结合等保 2.0 风险分级要求：

### 2.1 等级定义

| 等级 | 标识 | CVSS 分数 | 影响 |
|---|---|---|---|
| **高危** | [高危] | 7.0–10.0 | 可直接获取系统权限、敏感数据泄露、服务不可用 |
| **中危** | [中危] | 4.0–6.9 | 部分数据泄露、权限提升、绕过部分防护 |
| **低危** | [低危] | 0.1–3.9 | 信息泄露、轻微绕过、需复杂条件触发 |
| **提示** | [无] | 0.0 | 配置类、信息泄露类，不直接造成危害 |

### 2.2 评级维度

- **攻击向量（AV）**：网络 / 邻接 / 本地 / 物理
- **攻击复杂度（AC）**：低 / 高
- **所需权限（PR）**：无 / 低 / 高
- **用户交互（UI）**：无 / 需要
- **保密性影响（C）**：无 / 低 / 高
- **完整性影响（I）**：无 / 低 / 高
- **可用性影响（A）**：无 / 低 / 高

## 四、漏洞详情

### 4.1 漏洞详情模板（每个漏洞一份）

#### WL-001：SQL 注入漏洞

**基本信息**
| 项 | 内容 |
|---|---|
| 漏洞编号 | WL-001 |
| 漏洞名称 | 用户登录模块 SQL 注入 |
| 风险等级 | [高危] **高危**（CVSS 9.8） |
| 漏洞位置 | https://example.com/api/login |
| 影响范围 | 所有用户数据 |
| 漏洞状态 | 待修复 |
| 修复优先级 | P0 - 立即修复 |

**漏洞描述**
用户登录接口 `POST /api/login` 的 `username` 参数未做输入过滤与参数化查询，攻击者可通过构造恶意 SQL 语句绕过认证、读取数据库内容。

**漏洞证明（仅描述，不展示可执行 Payload）**
```
POST /api/login HTTP/1.1
Host: example.com
Content-Type: application/json

{"username":"admin' OR '1'='1' -- ","password":"x"}
```
服务端返回包含管理员信息的 JSON 响应，证明注入成立。

**漏洞截图**

>  此处粘贴漏洞验证截图（须脱敏处理：遮盖真实 IP、域名、用户名等敏感信息，仅保留验证结果关键部分）。

**风险分析**
- ✓ 攻击向量：网络（远程）
- ✓ 攻击复杂度：低（公开漏洞利用工具）
- ✓ 所需权限：无
- ✓ 用户交互：无需
- ✓ 保密性影响：高（可读取全部用户数据）
- ✓ 完整性影响：高（可篡改数据）
- ✓ 可用性影响：中（可触发数据库错误）

**修复建议**
1. **强制参数化查询（优先级最高）**：
   ```python
   # Python 示例
   cursor.execute("SELECT * FROM users WHERE username = %s", (username,))
   ```
2. **输入校验**：用户名限制为字母数字下划线
3. **最小权限原则**：数据库账号仅授 `SELECT/INSERT/UPDATE`
4. **错误信息脱敏**：生产环境关闭详细 SQL 错误回显
5. **WAF 防护**：部署 Web 应用防火墙（深度防御）

**修复验证方法**
修复后，重新执行相同 Payload：
- 返回「用户名或密码错误」
- 不返回数据库详细信息
- 数据库无异常查询日志

## 五、系统加固建议汇总

按优先级排序：

### 5.1 P0 - 立即修复（24 小时内）
1. 修复高危 SQL 注入漏洞（WL-001）
2. 修复文件上传漏洞（WL-002）
3. 移除测试环境残留的 webshell 后门

### 5.2 P1 - 一周内修复
1. 修复 XSS 漏洞（WL-003）
2. 修复 CSRF 漏洞（WL-004）
3. 修改所有弱口令（WL-005）
4. 部署 WAF

### 5.3 P2 - 一个月内修复
1. 修复信息泄露问题
2. 关闭不必要的服务端口
3. 完善日志审计系统

### 5.4 P3 - 持续优化
1. 建立漏洞管理流程
2. 定期安全评估（每季度）
3. 安全开发培训（面向研发团队）
