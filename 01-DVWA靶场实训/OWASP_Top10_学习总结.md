## 二、各条目详解 + 仓库映射

### A01 访问控制失效 

**原理**：用户能够访问其权限之外的资源或功能（如水平越权查看他人订单、垂直越权普通用户访问管理后台）。

**仓库证据**：
- `01-DVWA靶场实训/漏洞复现合集/CSRF跨站请求伪造.md` — 攻击者诱骗已登录用户执行未授权操作

**真实案例**：2018 年 Facebook "View As" 漏洞，访问令牌错误暴露 5000 万用户隐私。

**防御建议**：
- 默认拒绝所有访问
- 实施最小权限原则
- 记录访问控制失败日志
- 禁用 JWT 等令牌中的 `none` 算法
- CORS 配置严格化

---

### A02 加密失败 

**原理**：缺少加密或使用弱加密算法，导致敏感数据（密码、信用卡、个人信息）泄露。

**仓库证据**：
- `03-工具使用笔记/BurpSuite基础使用.md` 第 2.2 节 — CA 证书导入（HTTPS 抓包）
- `01-DVWA靶场实训/系统加固方案.md` — Apache HTTPS 配置

**常见错误**：
- HTTP 明文传输（应强制 HTTPS）
- 密码使用 MD5/SHA1（应使用 bcrypt/Argon2）
- 数据库字段未加密
- SSL/TLS 证书过期或自签名

**防御建议**：
- 强制 HTTPS（HSTS + 301 重定向）
- 使用 TLS 1.2+（禁用 SSLv3/TLS 1.0）
- 密码 bcrypt 加盐哈希
- 敏感字段 AES-256 加密存储

---

### A03 注入 （仓库重点）

**原理**：用户提供的数据作为代码或查询的一部分被执行，导致非预期行为。

**仓库证据**：
- `01-DVWA靶场实训/漏洞复现合集/SQL注入.md` — Union 注入 / 盲注 / 时间盲注（Low/Medium/High/Impossible 四等级）
- `01-DVWA靶场实训/漏洞复现合集/命令注入.md` — OS 命令注入四等级
- `01-DVWA靶场实训/漏洞复现合集/XSS跨站脚本.md` — 反射型 + 存储型 XSS 四等级

**注入类型谱系**：
```
注入攻击
├── SQL 注入（数据库）
├── NoSQL 注入（MongoDB）
├── OS 命令注入（系统）
├── LDAP 注入
├── XSS（脚本注入）
└── SSTI 模板注入
```

**真实案例**：2017 年 Equifax 数据泄露（1.43 亿用户）— Apache Struts2 OGNL 注入漏洞。

**防御建议（金科玉律：参数化查询）**：
- SQL：**永远使用预编译语句（PreparedStatement）**
- OS 命令：**避免拼接，使用白名单或 API**
- XSS：**输出编码 + CSP 头**
- 输入校验（白名单优于黑名单）

### A04 不安全设计 

**原理**：架构和设计层面缺少安全控制，无法通过完美实现来修复。

**仓库证据**：
- `02-等保2.0资料合集/等保测评基础规范笔记.md` — 等保 2.0 "一个中心、三重防护" 框架本身就是安全设计
- `01-DVWA靶场实训/风险评估报告模板.md` — 风险建模前置

**常见设计缺陷**：
- 缺少速率限制 → 被暴力破解
- 缺少账户锁定 → 被无限尝试
- 关键操作无二次验证 → 被 CSRF

**防御建议**：
- 威胁建模（STRIDE / PASTA）
- 安全设计评审
- 参考 OWASP ASVS（应用安全验证标准）

---

### A05 安全配置错误 （仓库重点）

**原理**：默认配置、不必要的功能开放、过时的安全补丁。

**仓库证据**：
- `01-DVWA靶场实训/系统加固方案.md` — **8 套加固方案**（Apache/MySQL/PHP/Linux/权限/日志/网络/DVWA 清理）
- `02-等保2.0资料合集/等保测评基础规范笔记.md` — Top 10 常见发现

**真实案例**：2017 年 WannaCry 勒索病毒（利用 SMB 漏洞 + 关闭的 445 端口）

**仓库加固清单**：
| 组件 | 加固项 | 仓库位置 |
|---|---|---|
| Apache | 隐藏版本号、禁用目录列表、限制 HTTP 方法 | 系统加固方案 §1 |
| MySQL | 删除匿名账户、限制 root 远程、绑定 127.0.0.1 | 系统加固方案 §2 |
| PHP | 关闭 display_errors、限制文件上传 | 系统加固方案 §3 |
| Linux | 密码策略、SSH 加固、iptables 规则 | 系统加固方案 §4 |

**防御建议**：
- 自动化配置管理（Ansible/Terraform）
- 定期漏洞扫描（Nessus/OpenVAS）
- 最小化部署（删除不需要的功能）

### A06 脆弱和过时的组件 

**原理**：使用含有已知漏洞的第三方库、框架、运行时。

**仓库证据**：
- `01-DVWA靶场实训/系统加固方案.md` §4.4 — 系统更新与补丁管理
- `01-DVWA靶场实训/环境部署文档.md` — Kali Linux + DVWA latest

**真实案例**：2017 年 Apache Struts2 远程代码执行漏洞（CVE-2017-5638）

**防御建议**：
- 使用 `npm audit` / `pip-audit` / `composer audit`
- 订阅漏洞公告（CVE / NVD / CNVD）
- 建立 SBOM（软件物料清单）
- 及时升级到安全版本

---

### A07 身份识别和认证失败 

**原理**：认证机制存在缺陷，允许攻击者冒充合法用户。

**仓库证据**：
- `01-DVWA靶场实训/漏洞复现合集/暴力破解.md` — 4 等级复现（Low 无限制 → Impossible 限速 + CSRF Token）
- `01-DVWA靶场实训/系统加固方案.md` — Linux 密码策略 + 登录失败锁定

**认证最佳实践**：
- 强密码策略（12+ 字符、混合复杂度）
- 多因素认证（MFA）
- 账户锁定（5 次失败锁 30 分钟）
- 密码 bcrypt 加盐（cost ≥ 12）
- Session 过期与轮换

---

### A08 软件和数据完整性失败 

**原理**：未验证关键数据和代码的完整性（如自动更新、反序列化、CICD 管道）。

**仓库证据**：
- `01-DVWA靶场实训/漏洞复现合集/文件上传漏洞.md` — 文件头检查、随机重命名、.htaccess 拦截

**真实案例**：2020 年 SolarWinds 供应链攻击（恶意代码植入合法更新）

**防御建议**：
- 数字签名验证（COSIGN / sigstore）
- CI/CD 管道安全（隔离构建环境）
- 反序列化白名单
- 文件上传：随机文件名 + 目录不可执行 + MIME + 文件头三重校验

---

### A09 安全日志和监控失败 （仓库重点）

**原理**：日志不记录、可视化、告警，导致攻击发生后无法溯源。

**仓库证据**：
- `01-DVWA靶场实训/日志审计分析.md` — **22 类异常日志模式**
- `04-合规辅助小脚本/日志简单解析.py` — 7 维度日志自动分析
- `02-等保2.0资料合集/安全现场巡检记录表.md` — 巡检异常记录

**仓库日志审计覆盖维度**：
1. Top 10 攻击源 IP
2. 异常 HTTP 方法
3. SQL 注入特征（`union`、`sleep`、`benchmark`）
4. XSS 特征（`<script>`、`onerror=`）
5. 路径穿越（`../`、`..\`）
6. 命令注入（`;`、`|`、`&&`）
7. 文件包含（`php://`、`file://`）
8. 扫描器 UA（Nmap/sqlmap/nikto）
9. 404 暴破检测（单 IP > 50 次 404）
10. Webshell 访问（`/upload/*.php`）
11. ...（共 22 类）

**防御建议**：
- 集中日志（ELK / Loki + Grafana）
- 关键事件实时告警
- 日志完整性保护（只追加存储）
- 保留周期 ≥ 180 天（等保三级要求）

---

### A10 服务端请求伪造（SSRF） 

**原理**：攻击者诱使服务器向内部系统发起请求，绕过访问控制。

**仓库覆盖**：[x] 概念级覆盖（见 [`扩展漏洞原理笔记.md`](扩展漏洞原理笔记.md)）

**典型场景**：
- 云环境元数据服务（`http://169.254.169.254`）
- 内网端口扫描
- 读取本地文件（`file:///etc/passwd`）

**防御建议**：
- URL 白名单
- 禁用不需要的协议（仅允许 HTTP/HTTPS）
- 解析主机名后再次校验 IP 是否在内网段
- 网络层隔离（出站防火墙）
