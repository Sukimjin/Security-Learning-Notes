| 编号 | 漏洞名称 | 风险等级 | CVSS 参考 | 影响 |
|---|---|---|---|---|
| WL-001 | SQL 注入 | 高危 | 9.8 | 可读取/篡改数据库全部数据 |
| WL-002 | 文件上传漏洞 | 高危 | 9.1 | 可上传 Webshell 获取服务器权限 |
| WL-003 | 命令注入 | 高危 | 9.1 | 可执行系统命令，控制服务器 |
| WL-004 | 文件包含 | 高危 | 8.1 | 可读取敏感文件/远程包含 |
| WL-005 | XSS 跨站脚本 | 中危 | 6.1 | 可窃取会话 Cookie、钓鱼 |

## 三、漏洞详情（节选代表性两项，其余见复现文档）

### WL-001：SQL 注入

| 项 | 内容 |
|---|---|
| 漏洞位置 | DVWA SQL Injection 模块（Low/Medium/High） |
| 风险等级 | 高危（CVSS 9.8） |
| 影响范围 | 后端 MySQL `dvwa` 库全部表 |
| 修复优先级 | P0 |

**漏洞描述**
用户输入直接拼接到 SQL 查询语句中，未做参数化，攻击者可构造恶意输入读取、篡改数据库内容。

**风险分析**
- 攻击向量：网络（远程）
- 所需权限：无
- 保密性影响：高（可读取全部数据）
- 完整性影响：高（可篡改数据）
- 可用性影响：中（可触发数据库错误）

**修复建议（防御视角）**
1. 强制参数化查询 / 预编译语句（PDO 或 mysqli 预处理）
2. 输入校验：限定参数类型与长度
3. 数据库账号最小权限，禁用 `FILE` 等危险权限
4. 错误信息脱敏，关闭详细 SQL 错误回显
5. 部署 WAF 做深度防御

**验证方法**
修复后相同输入返回「用户名或密码错误」，数据库无异常查询日志。

### WL-002：文件上传漏洞

| 项 | 内容 |
|---|---|
| 漏洞位置 | DVWA Upload 模块（Low/Medium） |
| 风险等级 | 高危（CVSS 9.1） |
| 影响范围 | 服务器文件系统、Web 服务进程 |
| 修复优先级 | P0 |

**漏洞描述**
上传功能未严格校验文件类型与内容，攻击者可上传恶意脚本文件并在服务器上执行。

**修复建议（防御视角）**
1. 白名单校验文件扩展名与 MIME 类型
2. 上传目录禁止脚本执行（Web 服务器配置）
3. 重命名上传文件，避免用户控制文件名
4. 文件内容二次渲染/杀毒扫描

## 四、系统加固建议汇总

按优先级（对应本仓库 [`系统加固方案.md`](系统加固方案.md)）：

### P0 — 立即修复（生产环境要求）
1. SQL 注入：全站参数化查询
2. 文件上传：白名单 + 禁执行 + 重命名
3. 命令注入：避免调用系统命令，必需时严格过滤
4. 文件包含：关闭远程包含，限定包含路径

### P1 — 一周内
1. XSS：输出编码 + CSP 策略
2. CSRF：关键操作加 Token 校验
3. 暴力破解：登录失败锁定 + 强口令策略

### P2 — 持续优化
1. 部署 WAF
2. 完善日志审计与告警
3. 建立周期性风险评估机制（每季度）

## 五、评估结论

本次评估在自有靶场内完成，确认 DVWA 7 类漏洞在 Low~High 等级下均可复现，危害评级与行业标准一致。靶场刻意保留漏洞用于复现练习，符合预期；本报告的价值是演示「如何对一个 Web 应用做风险评估并给出加固路线」，相关防御方案已在本仓库 [`系统加固方案.md`](系统加固方案.md) 中落地。
