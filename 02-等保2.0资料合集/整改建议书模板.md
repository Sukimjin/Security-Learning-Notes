### 1.2 整改原则

1. **高危优先**：高危不符合项 24 小时内启动整改，7 天内完成
2. **根因修复**：从根本原因着手，不采用临时规避
3. **最小影响**：整改过程不影响业务正常运行
4. **闭环管理**：每项整改均需验证并记录结果
5. **文档留存**：整改方案、操作记录、验证结果全程留痕

### 1.3 整改流程

```
测评发现问题 → 风险定级 → 制定整改方案 → 审批 → 实施整改
                                                    │
复测验证 ← 整改完成 ← 记录操作 ← ─────────────────┘
    │
    ├── 通过 → 关闭问题项
    └── 未通过 → 重新整改
```

## 三、整改措施详情

### 3.1 高危项整改方案

#### H-001：SSH 允许 root 密码登录

| 项目 | 内容 |
|------|------|
| **问题描述** | `/etc/ssh/sshd_config` 中 `PermitRootLogin yes`，允许 root 直接密码登录 |
| **风险分析** | 攻击者爆破 root 密码后可直接获取最高权限 |
| **整改措施** | 1. 修改 `PermitRootLogin no` 2. 修改 `PasswordAuthentication no`（改用密钥登录）3. 创建 sudo 普通用户 |
| **验证方法** | `grep PermitRootLogin /etc/ssh/sshd_config` 确认为 `no`；尝试 root 密码登录应被拒绝 |
| **回退方案** | 保留 root 密码登录配置备份，如需恢复可临时开启 |
| **参考文档** | [安全现场巡检记录表.md §附录A](安全现场巡检记录表.md) SSH 基线检查 |

#### H-002：MySQL root 可远程登录

| 项目 | 内容 |
|------|------|
| **问题描述** | `mysql.user` 表中 root 的 host 为 `%`，允许任意 IP 远程登录 |
| **风险分析** | 攻击者可从外网爆破 MySQL root 密码，获取数据库完全控制权 |
| **整改措施** | 1. `UPDATE mysql.user SET host='localhost' WHERE user='root' AND host='%';` 2. `FLUSH PRIVILEGES;` 3. 创建业务专用账号，仅授予最小权限 |
| **验证方法** | `SELECT user,host FROM mysql.user WHERE user='root';` 确认仅 localhost |
| **回退方案** | 记录原 host 配置，如业务需要可改为内网 IP 段 |
| **参考文档** | [安全现场巡检记录表.md §附录B](安全现场巡检记录表.md) MySQL 基线检查 |

#### H-003：防火墙存在 any-any-permit 规则

| 项目 | 内容 |
|------|------|
| **问题描述** | 边界防火墙规则中存在 `any → any → permit` 的全通规则 |
| **风险分析** | 等于无防火墙，所有流量均可通行，无法实现边界隔离 |
| **整改措施** | 1. 删除 any-any-permit 规则 2. 按业务需求逐条配置最小化 ACL 3. 默认策略改为 deny |
| **验证方法** | `show access-lists` 确认无 any-any-permit；测试业务流量正常 |
| **回退方案** | 保留旧规则配置备份，整改后如业务异常可临时恢复（需审批） |
| **参考文档** | [安全现场巡检记录表.md §3.1.2](安全现场巡检记录表.md) 防火墙巡检 |

#### H-004：核心系统无双因素认证

| 项目 | 内容 |
|------|------|
| **问题描述** | 核心业务系统管理员登录仅使用用户名+密码，无第二因素验证 |
| **风险分析** | 密码泄露后可直接登录系统，无第二道防线 |
| **整改措施** | 1. 部署 OTP/TOTP 动态口令 2. 管理后台启用双因素 3. 关键操作增加短信/邮件确认 |
| **验证方法** | 登录管理后台验证双因素流程；确认密码错误后无法通过第二因素 |
| **回退方案** | 保留原密码登录作为降级方案，双因素故障时可临时使用（需审批+记录） |

#### H-005：无数据备份恢复演练记录

| 项目 | 内容 |
|------|------|
| **问题描述** | 虽有数据备份，但从未进行恢复演练，无法验证备份可用性 |
| **风险分析** | 备份可能损坏或不完整，故障时无法恢复 |
| **整改措施** | 1. 制定备份恢复演练计划 2. 在测试环境执行全量恢复 3. 验证数据完整性 4. 记录演练过程与结果 |
| **验证方法** | 查看演练报告、恢复数据完整性校验记录 |
| **回退方案** | 演练在测试环境进行，不影响生产数据 |

### 3.2 中危项整改方案

#### M-001：密码策略未配置复杂度要求

| 项目 | 内容 |
|------|------|
| **问题描述** | 系统密码策略未要求大小写+数字+特殊字符混合 |
| **整改措施** | 配置 `pam_pwquality`：`minlen=8 minclass=3`；Windows 组策略启用密码复杂度 |
| **验证方法** | 尝试设置简单密码应被拒绝 |
| **参考文档** | [安全现场巡检记录表.md §附录A](安全现场巡检记录表.md) |

#### M-002：未启用登录失败锁定

| 项目 | 内容 |
|------|------|
| **问题描述** | 系统未配置登录失败锁定策略，可被无限次暴力破解 |
| **整改措施** | 配置 `pam_faillock`：5 次失败后锁定 30 分钟；Windows 组策略配置账户锁定 |
| **验证方法** | 连续输错 5 次密码后账户应被锁定 |
| **参考文档** | [安全现场巡检记录表.md §附录A](安全现场巡检记录表.md) |

#### M-003：部分管理通道使用 Telnet

| 项目 | 内容 |
|------|------|
| **问题描述** | 部分网络设备管理使用 Telnet，明文传输密码 |
| **整改措施** | 1. 关闭 Telnet 服务 2. 启用 SSH 3. 配置 ACL 限制管理源 IP |
| **验证方法** | 尝试 Telnet 连接应被拒绝；SSH 连接正常 |

#### M-004：日志留存不足 6 个月

| 项目 | 内容 |
|------|------|
| **问题描述** | 系统日志仅保留 30 天，不满足等保 ≥ 6 个月要求 |
| **整改措施** | 1. 调整 logrotate 保留周期 2. 日志转发至日志审计平台长期存储 3. 配置日志存储容量告警 |
| **验证方法** | 查看日志平台存储策略，确认 ≥ 180 天 |

#### M-005：应急预案超过 1 年未演练

| 项目 | 内容 |
|------|------|
| **问题描述** | 应急预案已制定但超过 1 年未进行演练 |
| **整改措施** | 1. 更新应急预案 2. 组织桌面推演 3. 记录演练过程与改进项 |
| **验证方法** | 查看演练记录、照片、改进措施跟踪表 |

#### M-006：未通过堡垒机集中运维

| 项目 | 内容 |
|------|------|
| **问题描述** | 运维人员直接 SSH/RDP 登录服务器，未通过堡垒机 |
| **整改措施** | 1. 防火墙仅允许堡垒机 IP 访问 22/3389 端口 2. 运维操作统一通过堡垒机 3. 配置操作审计录像 |
| **验证方法** | 直连服务器应被拒绝；通过堡垒机登录正常且有审计记录 |

### 3.3 低危项整改方案

#### L-001：Apache 未隐藏版本信息

| 项目 | 内容 |
|------|------|
| **整改措施** | `httpd.conf` 中设置 `ServerTokens Prod` 和 `ServerSignature Off` |
| **验证方法** | `curl -I` 检查响应头不含 Apache 版本号 |
| **参考文档** | [系统加固方案.md](../01-DVWA靶场实训/系统加固方案.md) Apache 加固 |

#### L-002：缺少 HTTP 安全响应头

| 项目 | 内容 |
|------|------|
| **整改措施** | 添加 `X-Frame-Options`、`X-Content-Type-Options`、`X-XSS-Protection`、`Strict-Transport-Security` |
| **验证方法** | `curl -I` 检查响应头包含上述安全头 |
| **参考文档** | [系统加固方案.md](../01-DVWA靶场实训/系统加固方案.md) |

#### L-003：系统存在多余测试账号

| 项目 | 内容 |
|------|------|
| **整改措施** | 清理 test/demo/temp 等非必要账号，删除对应家目录 |
| **验证方法** | `cat /etc/passwd | grep -E 'test|demo|temp'` 无结果 |

#### L-004：安全培训记录不完整

| 项目 | 内容 |
|------|------|
| **整改措施** | 补充安全培训计划，每半年组织一次，留存签到表与培训材料 |
| **验证方法** | 查看培训记录、签到表、培训材料 |
