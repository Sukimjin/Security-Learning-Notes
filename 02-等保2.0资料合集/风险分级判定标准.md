# 漏洞风险分级判定标准

> 适用场景：风险评估报告、等保测评、漏洞修复优先级排序
> 参考标准：CVSS 3.1、GB/T 22239-2019、OWASP Risk Rating

---

## 一、风险分级总览

### 1.1 风险 = 威胁 × 脆弱性 × 资产价值

```
风险等级 = f(资产价值, 威胁频率, 脆弱性严重程度)
```

### 1.2 三级等级划分

| 等级 | 标识 | 含义 | 处理时限 |
|---|---|---|---|
| **高危** | [高危] | 可直接造成重大损失 | 24 小时 |
| **中危** | [中危] | 可能造成局部损失 | 7 天 |
| **低危** | [低危] | 影响有限，需特定条件 | 30 天 |
| **提示/信息** | [无] | 配置类、不直接造成危害 | 视情况 |

## 二、CVSS 3.1 评分体系

### 2.1 CVSS 三维度

CVSS（Common Vulnerability Scoring System）从三个维度评分：

#### 基础维度（Base Score）

| 指标 | 取值 |
|---|---|
| **攻击向量 (AV)** | 网络(N) 0.85 / 邻接(A) 0.62 / 本地(L) 0.55 / 物理(P) 0.20 |
| **攻击复杂度 (AC)** | 低(L) 0.77 / 高(H) 0.44 |
| **所需权限 (PR)** | 无(N) 0.85 / 低(L) 0.62 / 高(H) 0.27 |
| **用户交互 (UI)** | 无(N) 0.85 / 需要(R) 0.62 |
| **保密性 (C)** | 无(N) 0.0 / 低(L) 0.22 / 高(H) 0.56 |
| **完整性 (I)** | 无(N) 0.0 / 低(L) 0.22 / 高(H) 0.56 |
| **可用性 (A)** | 无(N) 0.0 / 低(L) 0.22 / 高(H) 0.56 |

#### 生命周期维度（Temporal）

| 指标 | 取值 |
|---|---|
| **漏洞利用代码成熟度 (E)** | 未定义(X) / 未验证(U) 0.91 / 概念验证(P) 0.94 / 功能验证(F) 0.97 / 高(H) 1.00 |
| **修复状态 (RL)** | 未定义(X) / 官方补丁(O) 0.95 / 临时补丁(T) 0.96 / 变通方案(W) 0.97 / 不可用(U) 1.00 |
| **报告置信度 (RC)** | 未定义(X) / 未知(U) 0.92 / 合理(R) 0.96 / 已确认(C) 1.00 |

#### 环境维度（Environmental）

根据客户实际环境调整：
- 业务对 CIA 的依赖度
- 资产价值
- 业务影响
- 缓解措施

### 2.2 CVSS 评分对照

| 分值 | 等级 |
|---|---|
| 9.0 – 10.0 | **严重（Critical）** |
| 7.0 – 8.9 | **高（High）** |
| 4.0 – 6.9 | **中（Medium）** |
| 0.1 – 3.9 | **低（Low）** |
| 0.0 | **无（None）** |

## 三、风险等级判定矩阵

### 3.1 综合判定（CVSS + 业务影响 + 利用难度）

| 维度 | 高 | 中 | 低 |
|---|---|---|---|
| **CVSS 评分** | ≥ 7.0 | 4.0-6.9 | < 4.0 |
| **业务影响** | 核心业务 / 大规模数据 / 关基 | 重要业务 / 敏感数据 | 一般业务 / 普通数据 |
| **可利用性** | 公开 EXP / 工具一键利用 | 需特定条件 | 仅理论存在 |
| **数据敏感度** | 个人信息 / 支付数据 / 商业机密 | 内部数据 | 公开数据 |

### 3.2 漏洞示例分级

| 漏洞类型 | 典型 CVSS | 等级 | 说明 |
|---|---|---|---|
| SQL 注入（核心业务） | 9.8 | 高危 | 可直接拖库 |
| 文件上传（PHP Webshell） | 9.8 | 高危 | 可获取服务器权限 |
| 默认 / 弱口令（管理员） | 9.8 | 高危 | 可直接接管系统 |
| 远程命令执行（RCE） | 9.8 | 高危 | 可执行任意命令 |
| 反射型 XSS（公开页面） | 6.1 | 中危 | 需用户交互 |
| 存储型 XSS | 7.5 | [低危] ~ [中危] | 影响所有访问者 |
| CSRF（敏感操作） | 6.5 | 中危 | 需用户已登录 |
| 信息泄露（错误详情） | 5.3 | 中危 | 暴露版本、堆栈 |
| 目录列表 | 4.3 | 中危 | 暴露目录结构 |
| 缺少安全 HTTP 头 | 3.1 | 低危 | 需其他漏洞配合 |
| HTTP 协议明文（无敏感数据） | 3.7 | 低危 | 仅在公开数据场景 |

## 四、OWASP 风险评级方法

OWASP Risk Rating 综合考虑：

```
风险 = 威胁代理 × 攻击向量 × 漏洞影响 × 业务影响
```

### 4.1 威胁代理等级

| 等级 | 说明 |
|---|---|
| 高级 | 内部恶意员工、有组织犯罪 |
| 中级 | 黑客、脚本小子、有动机的员工 |
| 低级 | 自动化脚本、一般用户 |

### 4.2 漏洞影响等级

| 等级 | 描述 |
|---|---|
| 高 | 可完全控制系统、窃取所有数据 |
| 中 | 可获取部分权限、敏感数据 |
| 低 | 暴露少量信息 |

### 4.3 业务影响等级

| 等级 | 描述 |
|---|---|
| 高 | 财务损失、品牌损害、法律责任 |
| 中 | 客户信任下降、合规风险 |
| 低 | 少量不便、可忽略 |

## 六、修复优先级排序

### 6.1 优先级模型

```
P0 = 立即修复（24h）
P1 = 高优先级（7d）
P2 = 中优先级（30d）
P3 = 低优先级（季度内）
```

### 6.2 优先级判定矩阵

| 风险等级 | 资产价值 | 优先级 |
|---|---|---|
| 高危 + 核心资产 | 核心 | **P0** |
| 高危 + 重要资产 | 重要 | **P0** |
| 高危 + 一般资产 | 一般 | **P1** |
| 中危 + 核心资产 | 核心 | **P1** |
| 中危 + 重要资产 | 重要 | **P2** |
| 中危 + 一般资产 | 一般 | **P2** |
| 低危 + 核心资产 | 核心 | **P2** |
| 低危 + 一般资产 | 一般 | **P3** |

### 6.3 修复成本考量

| 因素 | 影响 |
|---|---|
| 修复影响业务 | 影响业务 → 排至维护窗口 |
| 修复工作量 | 大工作量 → 排至项目期 |
| 替代方案 | 有替代 → 可临时规避 |
| 攻击窗口 | 高频攻击 → 紧急处理 |

## 七、风险处置策略

### 7.1 接受风险（Accept）

适用情况：
- 低危漏洞 / 信息泄露类
- 修复成本远高于风险
- 业务影响极小
- **必须书面审批**：风险接受审批单

### 7.2 规避风险（Avoid）

适用情况：
- 漏洞在功能中不可消除
- 临时禁用受影响功能

### 7.3 转移风险（Transfer）

适用情况：
- 通过保险 / 第三方服务
- 责任转嫁给供应商
- **注意**：法律责任不可完全转移

### 7.4 缓解风险（Mitigate）

适用情况：
- 大多数漏洞首选
- 通过控制措施降低风险

**缓解措施**：
- 漏洞修复（补丁、配置调整）
- 部署 WAF（深度防御）
- 强化监控告警
- 限制受影响功能
- 增加访问控制

## 八、风险评级示例

### 8.1 示例 1：电商网站 SQL 注入

```
CVSS 评分：9.8（Critical）
攻击向量：网络（N）
攻击复杂度：低（L）
所需权限：无（N）
用户交互：无需（N）
保密性：高（H）
完整性：高（H）
可用性：无（N）
漏洞利用代码成熟度：功能验证（P）

业务影响：
- 资产价值：核心（核心交易系统）
- 数据敏感度：高（用户订单、支付信息）
- 业务影响：高（可拖库、篡改订单）

综合判定：高危 / P0 / 24h 内修复
```

### 8.2 示例 2：内部 OA 信息泄露

```
CVSS 评分：5.3（Medium）
攻击向量：网络（N）
攻击复杂度：低（L）
所需权限：低（L）
用户交互：无需（N）
保密性：低（L）
完整性：无（N）
可用性：无（N）

业务影响：
- 资产价值：重要（内部系统）
- 数据敏感度：中（内部信息）
- 业务影响：中（信息泄露但不影响核心）

综合判定：中危 / P2 / 30d 内修复
```

## 九、风险报告模板

```
漏洞编号：WL-2026-001
漏洞名称：用户登录模块 SQL 注入
风险等级：高危 / P0

CVSS 评分：9.8（Critical）
CVSS 向量：CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N

威胁代理：高级（外部黑客、有组织犯罪）
攻击向量：网络
攻击复杂度：低
所需权限：无
用户交互：无需

漏洞影响：
- 保密性：高（可读取所有用户数据）
- 完整性：高（可篡改数据）
- 可用性：无

业务影响：
- 业务功能影响：核心交易功能
- 数据敏感性：高（订单、支付）
- 财务影响：高（欺诈、退单、罚款）
- 品牌影响：高（用户流失）

综合风险等级：高危
修复优先级：P0
建议修复时限：24 小时

处置建议：缓解（Mitigate）
- 立即措施：WAF 临时规则拦截
- 根本修复：参数化查询

参考：CWE-89、OWASP Top 10 A03
```
