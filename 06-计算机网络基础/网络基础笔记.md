## 一、OSI 七层 vs TCP/IP 四层

| OSI 七层 | 功能一句话 | 典型协议 / 设备 | TCP/IP 四层对应 |
|---|---|---|---|
| 7 应用层 | 用户直接接触的软件接口 | HTTP / HTTPS / DNS / FTP / SMTP | 应用层 |
| 6 表示层 | 数据格式、加密、压缩 | TLS / SSL / JPEG / ASCII | （并入应用层） |
| 5 会话层 | 建立、管理、终止会话 | RPC / NetBIOS | （并入应用层） |
| 4 传输层 | 端到端可靠/不可靠传输 | TCP / UDP | 传输层 |
| 3 网络层 | 路由寻址、跨网转发 | IP / ICMP / 路由器 | 网际层 |
| 2 数据链路层 | 相邻节点帧传输、MAC 地址 | 以太网 / 交换机 | 网络接口层 |
| 1 物理层 | 比特流传输、电气特性 | 双绞线 / 光纤 / 集线器 | （并入网络接口层） |

**记忆口诀**：应、表、会、传、网、数、物（上 → 下）。
**关键点**：数据封装从上往下加头部；解封装从下往上摘头部。交换机工作在数据链路层（看 MAC），路由器工作在网络层（看 IP）。

## 二、三次握手

三次握手建立 TCP 连接：

1. **SYN**：客户端 → 服务器， seq = x，状态 `SYN_SENT`
2. **SYN + ACK**：服务器 → 客户端， seq = y， ack = x+1，状态 `SYN_RCVD`
3. **ACK**：客户端 → 服务器， seq = x+1， ack = y+1，双方进入 `ESTABLISHED`

**为什么是三次（不是两次）？**
防止已失效的连接请求报文突然又传到服务器，造成服务器误开连接、浪费资源。三次握手确认了双方的收发能力都正常。

**常见问题**：
- **半连接（SYN Flood）**：攻击者只发 SYN 不发第三次 ACK，服务器维持 `SYN_RCVD` 队列，耗尽资源 → 属于 DoS 攻击，防御靠 SYN Cookie / 限速。
- **TIME_WAIT**：主动关闭方发完最后 ACK 后进入 TIME_WAIT，等待 2MSL（报文最大生存时间 ×2），确保对端收到 ACK、让旧报文消散。高并发短连接服务（如 Nginx）TIME_WAIT 过多会占端口，可调整 `net.ipv4.tcp_tw_reuse` 等内核参数缓解。

## 三、四次挥手

TCP 全双工，关闭需双向各关一次，故四次：

1. **FIN**：主动方 → 被动方，请求关闭（进入 `FIN_WAIT_1`）
2. **ACK**：被动方 → 主动方（进入 `CLOSE_WAIT`，主动方进入 `FIN_WAIT_2`）
3. **FIN**：被动方 → 主动方，表示自己也发完了（进入 `LAST_ACK`）
4. **ACK**：主动方 → 被动方，进入 `TIME_WAIT`，等 2MSL 后 `CLOSED`

**为什么挥手是四次而非三次？** 因为被动方收到 FIN 后，可能还有数据要发（半关闭状态），不能立刻回 FIN，只能先回 ACK，等数据发完再发 FIN —— 所以 ACK 和 FIN 分两次。

## 四、TCP 与 UDP 区别

| 对比项 | TCP | UDP |
|---|---|---|
| 连接方式 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠（确认、重传、排序） | 不可靠、尽最大努力 |
| 速度 | 慢（有开销） | 快 |
| 流量/拥塞控制 | 有 | 无 |
| 首部开销 | 20 字节起 | 8 字节 |
| 应用举例 | HTTP / HTTPS / FTP / SMTP / SSH | DNS / DHCP / TFTP / 视频通话 / 游戏 |

**记忆**：TCP 像打电话（先接通再聊，丢了重说）；UDP 像发短信（发了就完，不管到没到）。实时音视频常用 UDP，网页/文件传输用 TCP。

## 六、子网划分实战

### 基础概念
- **IP 地址** = 网络位 + 主机位
- **CIDR**：`192.168.1.0/24` 表示前 24 位是网络位，后 8 位是主机位
- **主机数** = 2^(主机位数) − 2（减网络地址和广播地址）
- **子网掩码**：`/24` = 255.255.255.0

### 例题：把 192.168.1.0/24 划分成若干 /26 子网

- /24 主机位 8 位；/26 主机位 6 位 → 借了 2 位（2^2 = 4 个子网）
- 每个 /26 主机数 = 2^6 − 2 = 62 台
- 4 个子网：
  - 192.168.1.0/26（.0 ~ .63）
  - 192.168.1.64/26（.64 ~ .127）
  - 192.168.1.128/26（.128 ~ .191）
  - 192.168.1.192/26（.192 ~ .255）

**通用公式**：借 n 位 → 2^n 个子网；每个子网主机数 = 2^(原主机位−n) − 2。

### 另一类问法：给定主机数反推掩码
例：一个网段要容纳 50 台主机 → 主机位需满足 2^h − 2 ≥ 50 → h = 6（2^6−2=62）→ 掩码 = 32 − 6 = /26。

## 七、VLAN 与 路由交换基础

### VLAN（虚拟局域网）
- **作用**：在二层交换机上把一台物理交换机逻辑划分成多个广播域，隔离广播、提升安全、便于管理。
- **Trunk（干道）**：交换机之间互联的链路，承载多个 VLAN 的流量，靠 **802.1Q 标签**区分 VLAN ID。
- **Access 口**：接终端设备（PC/打印机），属于单一 VLAN。
- **典型场景**：办公网 / 财务网 / 访客网分 VLAN，访客网不能访问内网。

### 交换机 vs 路由器

| 对比 | 交换机（Switch） | 路由器（Router） |
|---|---|---|
| 工作层级 | 数据链路层（二层） | 网络层（三层） |
| 寻址依据 | MAC 地址 | IP 地址 |
| 主要功能 | 局域网内帧转发、VLAN | 跨网段路由、NAT、防火墙 |
| 隔离广播 | VLAN 内不隔离，VLAN 间隔离 | 天然隔离广播域 |
| 典型位置 | 楼栋 / 机房接入 | 网络出口、网段互联 |

**补充**：三层交换机 = 交换机 + 部分路由功能（VLAN 间路由），但出口仍靠路由器做 NAT 连外网。
