# 流量分析基础（Wireshark / tcpdump）

> 记录 Wireshark / tcpdump 的基本用法和异常流量识别方法，配合日志做攻击溯源。仅用于授权环境 / 自有流量分析。

---

## 一、为什么需要流量分析

日志记录的是「谁、在什么时候、做了什么」的**应用层**信息，而流量（抓包）能看到**原始报文**：完整请求内容、隐藏字段、加密前的明文、异常协议行为。两者结合能更完整地还原攻击链路。

| 场景 | 价值 |
|---|---|
| 攻击溯源 | 还原攻击请求的完整载荷与来源 |
| 异常识别 | 发现扫描、爆破、隧道、外连等异常流量 |
| 业务排障 | 定位请求失败、响应异常原因 |

## 二、tcpdump 基础命令

```bash
# 抓取指定网卡流量
sudo tcpdump -i eth0

# 只抓 80 端口
sudo tcpdump -i eth0 port 80

# 抓取指定主机
sudo tcpdump -i eth0 host 192.168.1.100

# 保存到文件（供 Wireshark 分析）
sudo tcpdump -i eth0 -w capture.pcap

# 读取文件
tcpdump -r capture.pcap
```

常用过滤：`tcp` / `udp` / `icmp`、`src` / `dst`、`port` / `portrange`、逻辑组合 `and` / `or` / `not`。

## 三、Wireshark 基础操作

1. **打开抓包文件**：File → Open（支持 pcap / pcapng）
2. **显示过滤器**（只显示符合条件的报文）：
   - `http` — HTTP 流量
   - `dns` — DNS 查询
   - `tcp.port == 80` — 80 端口
   - `ip.addr == 192.168.1.100` — 指定 IP
   - `http.request.method == POST` — POST 请求
3. **追踪流**：右键报文 → Follow → TCP/HTTP Stream，看完整会话
4. **统计**：Statistics → Conversations / Protocol Hierarchy，看流量分布

## 四、异常流量识别要点

| 异常特征 | 可能的攻击行为 |
|---|---|
| 单 IP 大量 404 / 探测路径 | 目录爆破 / 扫描器 |
| 单 IP 高频登录请求 | 暴力破解 |
| 大量 DNS TXT / 长域名 | DNS 隧道（数据外传） |
| 异常外连（非业务端口 / 境外 IP） | 后门回连 / C2 |
| HTTP 请求含 SQL 关键词 / 编码载荷 | SQL 注入探测 |
| 大量 SYN 未完成握手 | SYN Flood（DDoS） |

识别思路：先看「谁在大量访问」→「访问了什么」→「请求内容是否异常」→ 结合日志定位具体攻击。

## 五、与日志审计联动

- 日志给出**告警线索**（如某 IP 大量 404）→ 用流量**回放该 IP 的完整请求**确认攻击载荷
- 流量发现**可疑外连** → 用系统日志 / 进程信息定位发起进程与后门位置

## 六、合规提示

- 只分析**自有流量或已授权环境**的流量
- 抓包可能包含敏感信息（账号、Cookie、明文密码），分析后及时销毁、不外传
- 生产环境抓包需评估性能影响与合规要求
